# v0.5.0

Ultimate Chess 3D, Alice no País das Maravilhas, Rally Master Pro and the Quake menu work again,
and the water in Bóia Cross gets the console's color. Loading a save state and using rewind no
longer bring back the previous sound and a black screen, and pausing now stops the music. The
restart-game shortcut arrives, in Qt and on Android.

**The Qt interface gets a new look and save states.** Themes, menus, toolbar and status bar,
settings with a sidebar, and the game opens in the main window itself. Save states arrive in Qt
with ten slots per game and keyboard shortcuts, and Android goes from five to ten slots.

**The old egui interface is gone.** The emulator now has a single interface, the Qt one, which had
already been the main one since v0.4.0 and is the one that gets the new features.

For those who used the egui interface (the `zeebx` program, the `zeebx-standalone-egui` package or
the `zeebxteam/tap/zeebx` cask):

- it stays at v0.4.2 and **will not get updates**. The emulator doesn't swap one interface for the
  other by itself;
- to keep getting new versions, install the Qt interface from the releases page
  (`zeebx-standalone-qt-…`) or through the `zeebxteam/tap/zeebx-qt` cask. The settings, the games
  folder and the saves are the same, and it finds them without you doing anything;
- afterwards, the egui version can be uninstalled.

For those working on the code: the command line (`zeebx run`, `zeebx session`, `zeebx bench`) still
exists, now in `frontends/cli`, and builds without Qt.

New:

- **PlayStation Vita**: an app that opens on its own (`zeebx-vita.zip`, a VPK for a Vita with
  Homebrew) and a core for the Vita's RetroArch (`zeebx_libretro-vita.zip`). The games go in
  `ux0:data/zeebx/roms`. The speed on the device hasn't been measured yet, and heavy games like
  Quake may not fit in the Vita's memory. A save state from the Vita doesn't open on the other
  platforms, nor theirs on the Vita
- **Save states in Qt**: ten slots per game. F1 saves, F3 loads, F2 and Shift+F2 switch slots and
  F4 undoes the last load, putting the game back the way it was before it. On macOS they are ⌘S,
  ⌘L, ⌘], ⌘[ and ⌘Z. All of them can be changed in the Shortcuts tab, which now accepts key
  combinations. Whoever already used F1 to F4 on a Zeebo button keeps the button, and the shortcut
  is left without a key. The slots are also in the System menu, with the size of each one. The
  states go in the same folder and in the same format as Android: a state copied from the phone
  opens on the computer, in the same slot
- **Ten save state slots on Android**, instead of five. The five from before stay where they were
- **The game opens in the main window**, in place of the library, and closing the game brings the
  library back. In fullscreen the bars go away. Whoever prefers the separate window from before
  will find the option in Graphics > Game in a separate window
- **Themes** in Settings > General > Theme: System (the previous look, and the default), Light,
  Dark, AMOLED, Orange, Blue, Ruby and Emerald. Orange and Blue come from the Zeebo itself, from
  the console's box and the lit-up logo. You can create your own theme with a `.json` in the
  `temas` folder of the settings
- **Menus and bars in the main window**: File, System, Settings, View, Tools and Help. System
  pauses, restarts, turns fast-forward on and off, takes a screenshot and closes the game. With a
  game open, the status bar shows its name, whether it is drawn on the graphics card or on the
  processor, and the speed. About became a dialog in the Help menu, and Check for updates also
  answers when there is no new version
- **Settings with a sidebar**: the tabs at the top became a column of categories, and the
  explanation of each option appears in the footer, the one for the option under the mouse or
  with keyboard focus
- **Restart the game**: in Qt, the R key restarts the open game right away (changeable in the
  Shortcuts tab); on Android, the Restart button is in the "back" box. What the game saved stays
  saved. Whoever already used R on a Zeebo button, in the global settings or in a game's, keeps
  the button, and restart is left without a key
- **Pause gets a symbol** in Qt: P shows a ⏸ in the middle of the screen while the game is paused,
  and on resuming a ▶ appears for a moment. Restarting shows a ↻
- **Keys in the Qt library**: X opens the chosen game's settings, C the details, and the Menu key
  or Shift+F10 the game's menu, in the grid and in the slider

Bugs fixed:

- **Loading a save state left the previous sound playing.** The music from the scene you left
  kept going on top of the loaded one, and a looping sound never stopped. Now loading silences
  what was playing and plays again what the state had playing
- **On Android, loading a save state of a game drawn on the graphics chip could come back with
  the screen of an old frame, or black.** The state now keeps the image from the instant it was
  saved
- **Ultimate Chess 3D: capturing an opponent's piece crashed the game** with "ARM core
  exception", and after that it wouldn't open anymore ("invalid access at 0x00000014"). There were
  two things: the game writes its log through an ARM-mode call the emulator didn't recognize,
  and, with a saved match, the game's file list ended at the save and hid the ones for the pieces
- **Alice no País das Maravilhas: the bottom part of the levels didn't exist.** Black strips at
  the foot of the screen and under the water, and in level 2 Alice went through the crack and fell
  forever into a room with no floor. The emulator cut one of the game's strings at 4 KB, and the
  map of each level arrived only halfway
- **With the rasterizer on the graphics card, the screen could flicker between the scene and
  black** — in Ultimate Chess 3D at any internal resolution, and black for good at 1x. The window
  showed the frame the game was still drawing, and not the last finished one; now it shows the
  last finished one, like the console. With rewind on, the flicker also came once per second,
  when it saved the point
- **Zeebo Extreme Bóia Cross: the water came out the wrong color.** On the first track (Santo
  André) it was purple-blue and opaque; on the console it is brown and murky, with the relief of
  the waves. On the second track the emulator showed the riverbed through the water, and on the
  console it is gray-blue and opaque. The game paints the water by combining two textures, one for
  relief and one for color, and the emulator mixed the two the wrong way: the color one never
  showed up. Applies on the processor and on the graphics card
- **Fast-forward seemed to speed up gradually**: the game was already running at the requested
  speed, but the sound and the ▶▶ label took a second and a half to catch up. Now both start
  together with it
- **Pausing the game didn't stop the sound**: the image stopped, but the music kept playing, and
  on resuming the sound could fall out of step with the game. Now pause stops both, in Qt and on
  Android, and the music resumes from where it stopped
- **Quake: the HOME button didn't open the menu in the middle of a level**, and without the menu
  you couldn't save or load. There were two things. Quake only recognizes HOME by a different code
  from the one the emulator sent, and Double Dragon only by the other; now HOME sends both, as the
  real controller must do. And releasing button 2 reached the game as another press of the menu
  key, which got stuck and made the game ignore HOME from then on (#95)
- **Rally Master Pro froze or closed after a few races**, on the scene change, with "invalid
  access at 0x0101010d". The game keeps one piece of information per texture in a list of 248
  positions, and the emulator numbered the textures without ever reusing the deleted ones: after a
  few stages the number went past 248, and the game wrote over its own memory. Now the numbering
  reuses them, like the console's (#95)
- **A controller turned off and back on with the emulator open didn't come back** on Linux, until
  the emulator was restarted. It happened with Nintendo controllers when `joycond` is installed, as
  is common on Arch and derivatives: the controller arrives locked and is only released a second
  later, and the controller reading didn't try again. Now it does
- **In Qt, changing the key of a shortcut or a button could stay on "Waiting" forever**, with the
  settings window without keyboard focus — for example, when opened from the welcome notice.
  Clicking "Change" now brings the keyboard to the window
- **Rewind didn't work in Qt**: going back a point rebuilt the game's textures outside its video
  context
- **Rewind left the screen black** in games drawn on the graphics card, like Magical Drop III and
  Um Jogo de Ovos, and sometimes took a step **forward** in the middle of going back
- In Qt, the tooltip text disappeared with a system theme with dark tooltips and a light window
- With session recording on, the report now lists the controllers the emulator sees and the first
  button of each one, and a button change that waits 5 s with no controller signal suggests what
  to try (USB cable, closing Steam and PS Remote Play, pairing again). It is the first step for
  the PS4 controller that doesn't respond on the Mac (#59). The report also warns when the game
  runs at less than half speed, with the frameskip and the cost of each frame

For those working on the code: the memory the emulator allocates for itself in the game's space
(thread stacks, buffers, the GL strings) left the game heap and went to a region of its own. That
way the address of what the game allocates stops changing from one emulator version to another,
which is what RetroAchievements needs in order to read memory. A save state saved in this version
doesn't open in an earlier one.
