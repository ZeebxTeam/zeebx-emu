# v0.6.0

The Z-Wheel now shows your games. The game grid and the 3D stage list what is in your ROM folder,
instead of the 59 titles the Zeebo store sold, and a game the store never had a slide for gets one
made from its box art and name. The Setup screen comes to life: the registration keyboard types,
the Shop no longer seems to hang, and message boxes read like the console's. The iPhone and iPad
app catches up with Android, and the emulator can now follow a daily build if you ask it to.

New:

- **The Z-Wheel's game grid lists the games you have.** Before, it always showed the store's 59
  titles in the same order, whatever the ROM folder held, and choosing one that wasn't there
  opened nothing. Now each game in the folder shows up once — with the store's box art and title
  when the store knew it, by its file name when it is a homebrew — and what is not in the folder
  doesn't show up. A game that comes back to the folder comes back to the grid, keeping its play
  count. With no game at all, the Z-Wheel shows its own notice, "Não há nenhum aplicativo em seu
  console"
- **The 3D stage follows the same list.** It showed the same fifteen slides for everyone, with
  Crash Bandicoot and Rally Master Pro twice. Now it shows one slide per game you have. Measured
  with 61 games: 12 with the store's own slide
- **A slide for every game.** A game the store had no slide for gets one made by the emulator: a
  framed panel with its box art and name, and its box art on the top reel. This is ours, not the
  console's — a Zeebo only showed what the store sent. Measured with 61 games: 48 slides made, no
  fault in 150 s on the stage
- **The registration on the Setup screen works**: the on-screen keyboard types and erases with the
  controller, the birth date lists move and keep the choice, and Back leaves the keyboard without
  crashing a few seconds later
- **Message boxes look like the console's**: the screen behind stays visible, long text wraps and
  scrolls with the arrows (with its scroll bar), and each text is drawn at its own size, with
  smooth edges
- **On iPhone and iPad, the app has what Android has.** Before, it was a list of names and a
  screen with fixed buttons. Now:
  - the library is a grid with box art and a search field, and a connected controller moves
    through it;
  - there is a settings screen, with the same sections and the same options as the other
    versions, in the same four languages;
  - the controls drawn on screen are Android's: the D-pad, two sticks, the four buttons, ZL, ZR
    and HOME. You choose when they show, their size and how see-through they are, and you can
    drag each one where you want it;
  - a button at the top opens a menu to pause, restart or close the game, and to save and load
    in ten slots, each with a picture of where you were;
  - fast-forward, rewind and turbo work, from a button on screen or from the controller;
  - with a real controller, each Zeebo button can be given to the controller button you prefer.
    Android doesn't have this yet
- **You can choose to receive the daily build.** In the settings, under Updates, "Update channel"
  is Stable or Nightly. Stable is what it always was: you are told when a version is released.
  Nightly also brings the build made every day from what is being worked on — it has what is
  coming first, and nobody has checked it yet. On Windows, on the AppImage and on the Mac it
  installs itself, like a release

Bugs fixed:

- **Shop, Buy, Check balance and Refill card seemed to hang.** The Z-Wheel was already showing
  "Não foi possível conectar à rede", but releasing the key that opened the box closed it at once.
  The same release used to answer the language box on its own; now that box waits for your choice,
  and choosing "Sim" no longer crashes the Z-Wheel
- **Help and News crashed** as soon as they opened
- On the Setup screen, all the rows no longer move together, and the text of a box no longer hides
  under its frame
- **Zenonia** lost its box art and title in the Z-Wheel and showed up as a bare file name
- On Android, the folder picker, the access request and a few buttons are now shown in the chosen
  language
- **Going in and out of the registration several times crashed the Z-Wheel**, after painting pink
  blocks over the screen. The second visit also drew the console number without its box
- **The Z-Wheel's menu music** was cut short, or left a moment of silence, each time it came
  round. It now loops without a seam. This one was measured, not heard: tell us if it still skips

Changed:

- **"Include pre-release versions" is gone from the settings.** Every version so far went out
  marked that way, and the option existed to make them count. From this one on a version is
  published as a version, and what is not ready for everyone goes out on the nightly channel. If
  you never touched the option, nothing changes for you: you are on Stable

Still missing:

- the Z-Wheel needs the network for the Shop, the registration's "Confirmar" and the "Sim" in the
  no-games notice, and waits there forever; Navegar does not open
- a homebrew has no box art in the grid
- on iPhone and iPad: games still draw their 3D without the graphics card, so the options that
  depend on it are not there; the ROM folder is always `roms` inside the app; and the settings
  and the pause menu are touched, not driven by the controller
- the nightly build is only made for the computer versions. Android, iPhone, the Vita and the
  RetroArch cores still come out with each release
- the slides made by the emulator take about 28 MB for 48 games, and a game's slide stays on disk
  after the game leaves the folder

For those working on the code: the codebase, its documentation and its build files are now in
English. The old Portuguese options of `zeebx` and `ZEEBX_*` variables keep working, and nothing
stored on disk changed names. The BREW core moved to the `zeebx-core` crate (0.1.3), and the game
heap size is now set by the emulator's loader. The iOS frontend keeps its decisions in Rust, where
`cargo test -p zeebx-ios` reaches them on any host, and leaves Swift to draw. `nightly.yml` builds
the Qt packages every day from `development` into a single release tagged `nightly`; a release is
now published without the pre-release mark, or the updater does not count it.
