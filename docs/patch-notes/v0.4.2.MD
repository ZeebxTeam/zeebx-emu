# v0.4.2

> Draft: notes what has already gone into `development` since v0.4.1.

Android gets on-screen controls, and Crash Nitro Kart is back to v0.4.0's speed. On the computer,
the emulator now updates itself and the windows come back at the size they were left. Fast-forward,
rewind and turbo arrive, each game can have its own settings, and the Need For Speed Carbon career
and the bosses in Um Jogo de Ovos start working.

New:

- **On-screen controls on Android**, for those who play without a physical controller: D-pad,
  both sticks, buttons 1 to 4 in a group and HOME at the top. An editor lets you put each piece
  wherever you want and change the size of each one. On a stick, the physical controller has
  priority: the on-screen one only counts when the physical one is at rest
- **Automatic updates** in the AppImage, the Windows installer and the macOS .app: the emulator
  downloads and installs the new version by itself, and only accepts packages signed by the
  release
- **Windows come back at the size they were left**, both the main one and the game one, in egui
  and in Qt. The size is only saved in windowed mode; maximized or fullscreen, the window opens at
  the screen's size. With no saved size, the game window opens at 640×512 in both frontends
- **Record each session to a file**, in the Debug tab: each game opened gets its own `.log`, with
  name, ID, UTC date and time in the header and the time on each line. It records the process and
  game memory every 10 s, the errors, the crashes and the emulator report at the end. It's meant
  to be sent along with a report of a freeze after a long time playing; the button next to it
  opens the folder
- Every package now carries the GPLv3 license and the licenses of the libraries used, in a
  `THIRD-PARTY-NOTICES.txt`
- **Fast-forward**: holding F10 speeds the game up from 2x to 10x (3x by default), or without
  limit. The sound speeds up along with it, higher pitched, or goes mute, as you prefer. The
  speed, the hold or toggle mode and "no sound" are in the Speed tab. On Android, a ▶▶ button on
  screen does the same
- **Rewind**: with it turned on in the Speed tab, holding F8 takes the game back point by point —
  one point per second of play, by default. It comes off because each point costs a hiccup of a
  few milliseconds and memory. What the game wrote to disk, like the save, doesn't go back. On
  Android, a ◀◀ button on screen
- **Turbo**, in RetroArch's three modes: classic (hold turbo together with the button), toggle (a
  tap turns the button into turbo) and hold (the button fires by itself while turbo is held). From
  5 to 20 presses per second, counted in game time: in fast-forward the turbo keeps the right
  rhythm. On Android, a TURBO button on screen
- **Shortcuts tab**, with all the game window's keys in one place. Fast-forward and rewind also
  accept a button on any connected controller; the screenshot stays keyboard only
- **Per-game settings**, in Qt: right-click a game in the grid, or press button 2 (X) on the
  controller in the library, and choose Configure. Checking "Use custom settings for this game",
  controls, graphics, speed and audio apply only to it, starting from a copy of the global ones.
  The other games keep the global ones
- **Game details**, through the same menu or button 3 (Y): ClassID, module ID, file, size and
  whether it has its own settings
- **Frame limit** of 60, 30 or off, and **frame skip** (automatic or fixed), which only the
  RetroArch core had before, now on the computer, on Android and in headless. The old "Hold at
  console speed" becomes the 60 limit, and whoever had it off stays without a limit

Bugs fixed:

- **3D games stopped after about 10 minutes** with "probable repeat loop", and the progress that
  hadn't been saved was lost. That was the case with Ridge Racer after the second lap. The
  emulator counted every call the game made since it opened and stopped at 200 million, which a
  3D game reaches in that time. Now the limit only catches the game that gets stuck without
  yielding

- **Slowdown in 3D, especially on Android.** The Iron Sight fix in v0.4.1 had cost about 30% of
  the speed in games that call the system a lot: Crash Nitro Kart in a race dropped from 385% to
  296% in the speed test. Now it's back to 391%, and Iron Sight keeps working
- On Android, the game could draw with the viewport, the clipping and the transparency the
  interface had left behind, because the interface and the game use the same graphics chip. The
  same went for headless with a window
- On Android, the on-screen controls sat on top of the "back" box (save states, stop the game)
  and stole the touch from its buttons. Now they disappear while the box is open
- The new version notice works again: the check failed when the latest published version was a
  pre-release
- **Loading a save state didn't bring back the whole game clock.** The game came back with the
  current time, and everything it had scheduled to happen — an effect, an animation — fired all at
  once right after loading. In Double Dragon, a state saved at 20 s came back at 25 s. Save states
  saved by this version come back at the right instant; old ones keep loading as before
- **With the speed limit off, the game didn't go much past the monitor's rate**, because the
  window ran one game frame per refresh. Now it runs as fast as the computer can take
- **Need For Speed Carbon: the career didn't progress after the intro races.** The car selection
  screen opened with a garbage name and empty bars, and the map said "win 286973016 races". Now the
  career screens open filled in
- **Um Jogo de Ovos froze when going to the first boss**, after stage 1-5: none of the boss scenes
  loaded. Now they load
- **FIFA 09: the player's name disappeared from the scoreboard** when they had a first and last
  name, like "K. Chafni"; only single-name ones, like "Chris", showed up. Names with accents also
  came out wrong
- **Peggle** with video on the graphics card: the backgrounds didn't show up and the previous
  screens stayed underneath. In **Treino Cerebral**, pieces of the screen disappeared and the
  buttons got light lines at the seams
- In Qt, the tooltips for the top bar buttons came out on a single line, wider than the screen.
  Now they wrap, like the ones on the library cards

For developers:

- `--trace` in `session` now works; before, it accepted the option and did nothing
