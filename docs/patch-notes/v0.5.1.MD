# v0.5.1

A security release. A game opened in the emulator could read, overwrite and delete files outside
its own folder. Now each game sees only what is its own, and the saves of all games now live in a
single place.

Bugs fixed:

- **A game can no longer reach the computer's files.** A `.mod` opened outside a package,
  straight from a folder like `Downloads`, could tamper with the files next to it: read them,
  change their contents and delete them. In a `.zip` package, it could delete the game's own
  files. No game in the library does this, but a `.mod` of unknown origin could. Now:
  - the game only reads what came with it, and cannot change or delete those files;
  - everything the game writes goes to the emulator's saves folder;
  - shortcuts (symbolic links) inside the game folder are ignored;
  - a save state edited by hand doesn't reopen files outside what the game can reach.
- **The saves of all games are kept together**, in `saves/mod/`, one folder per game, as on the
  console. A game that uses another's save, like Zeebo F.C. with the Zeeboids characters, still
  finds what it needs
- **Quake's progress is kept with the other saves.** Before, it went to the extracted game's
  folder and was lost when that folder was deleted
- **Armageddon Squadron**: the terrain no longer shows up split into light and dark rectangles.
  The lighting in 3D games fell on the wrong side of rotated objects, and on the terrain, drawn in
  blocks, that turned into shadows out of place. Applies to every game that lights the scene
  through the console

For those who already had saves:

- the first time each game opens in this version, its saves are copied to the new place
  automatically. Nothing is deleted: the old copy stays where it was, and no save in the new place
  is overwritten
- two versions of the same game now share the same save, as they would on the console
- a save state made in an earlier version with the game writing to a database may not load. This
  doesn't affect the game's normal save
